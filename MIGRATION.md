# Helix ADK Migration Guide

To port the Operational Risk Multi-Agent System into a project scaffolded by your internal **Helix ADK kit**, you'll want to isolate the custom logic we wrote and drop it into the skeleton provided by your company.

Since Helix ADK handles all the enterprise boilerplate (authentication, CI/CD, deployment targets, enterprise guardrails), here is the exact step-by-step guide to migrate our components into your new Helix environment:

### Step 1: Scaffold the Helix Starter Agent
In your work environment, use your company's standard command to create a new Helix ADK project (e.g., `helix-cli scaffold ...`). This generates a project with your corporate structure, dependency files, and deployment manifests.

### Step 2: Migrate Dependencies
Open the dependency file generated by Helix (usually `pyproject.toml` or `requirements.txt`) and add the specific packages we used for our data engine and export tools.
Append these to the dependencies list:
* `duckdb` (for the in-memory SQL engine)
* `pandas` (for dataframe handling)
* `pyyaml` (for dynamic agent loading)
* `reportlab` (for PDF exports)
* `python-pptx` (for PowerPoint exports)
* `openpyxl` (optional, if you plan to use Excel as data sources)

*Run your environment sync command (e.g. `uv sync` or `pip install`) after adding these.*

### Step 3: Copy Core Logic Files
From our `dart-ops` project, copy these isolated files directly into the directory where your Helix agent logic lives (often an `app/` directory or the root):
1. **`db_helper.py`** (The DuckDB loader and query engine)
2. **`registry.py`** (The dynamic registry that loads the agents and binds the database tools)
3. **`tools.py`** (The custom python execution tool and the PDF/PPTX exporters)

### Step 4: Copy Configs and Data
Copy the two asset folders into the same level as your agent code:
1. **`config/`** (Contains `agents/` and `reviewers/` YAML files)
2. **`data/`** (Contains your CSV files)

### Step 5: Adapt the Main Agent Coordinator
Helix will likely have generated a default `agent.py` (or similar main entry point file).

1. Open our `agent.py` and copy the `OperationalRiskCoordinator` class.
2. Paste it into the Helix `agent.py`.
3. In our `agent.py`, we construct the path to the config files like this:
   ```python
   config_path = os.path.join(os.path.dirname(__file__), "config", "agents")
   ```
   **Crucial check:** Ensure this path correctly points to the `config/agents` folder relative to wherever Helix placed your `agent.py`.
4. Ensure the Helix entry point exposes our coordinator. For example, if Helix looks for a variable named `agent`, make sure the bottom of the file has:
   ```python
   agent = OperationalRiskCoordinator()
   ```

### Step 6: Test in Helix
Run your internal local testing command. Because we built our `OperationalRiskCoordinator` strictly adhering to standard ADK `BaseAgent` and `Event` semantics, it should plug natively into the Helix runner and state mechanisms without any architectural rewrites.
